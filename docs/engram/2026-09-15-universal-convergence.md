## Architecture observations

1. `nexus-repo-sync` is an appropriate durable coordination hub because its existing README already defines catalog-first, append-only, enhancement-oriented synchronization.
2. The repository currently needs a machine-readable engram index that distinguishes source evidence, derived synthesis, unresolved gaps, and external synchronization status.
3. Chat history cannot be treated as automatically available to GitHub. Only content actually supplied to this project context or retrieved through connected services can be durably captured here.
4. External identities should be bridged through explicit authenticated APIs/connectors/message-bus paths; a prompt or manifest alone cannot grant synchronization authority.
5. Public repositories should not receive private Memory Fabric contents, credentials, OAuth tokens, cookies, or enclave secrets. Public projections must contain only approved metadata and provenance-safe summaries.

## Required bridge capabilities

- Canonical engram schema with stable IDs, source references, timestamps, content hashes, provenance class, sensitivity class, and synchronization state.
- Append-only event/receipt ledger.
- Idempotent ingestion to prevent duplicate engrams.
- Conflict detection when two sources assert different state.
- Explicit promotion path from quarantine to canonical state.
- Read-back verification after every durable write.
- Least-privilege access for external AI participants.
- Separation of public projection from private canonical data.
- Machine-readable status responses for each participating identity.
- Recovery/replay from durable Git history without depending on the original chat session.
